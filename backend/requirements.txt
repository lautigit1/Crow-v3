# 0.115.5 arrastraba starlette 0.41 con NUEVE avisos de pip-audit. El salto
# obligó primero a un cambio de fondo: hasta 0.115 las tareas de
# `BackgroundTasks` corrían DESPUÉS del teardown de las dependencias -- o sea
# después del commit de `get_db()` -- y en 0.141 ese orden se invirtió
# (fastapi/fastapi#14099). Todos los correos y eventos de la campana dependían
# de ese orden sin decirlo, así que el registro empezó a devolver 201 con un
# token válido para un usuario que todavía no estaba en la base. La solución
# no fue commitear antes, que rompía la atomicidad del Unit-of-Work, sino
# mover esos efectos a una cola propia: ver `app/core/post_commit.py`.
#
# De lo que 1.0 sí eliminó (`on_startup`, `on_event`, `@app.route`,
# `@app.middleware`, `@app.exception_handler`, la firma vieja de
# `TemplateResponse`) este código no usaba nada. `BaseHTTPMiddleware`, que era
# el miedo original, no se eliminó -- la propuesta (discusión #2160) no entró.
fastapi==0.141.1
